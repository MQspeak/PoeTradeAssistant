# 可视化自动化流程编辑器设计

日期：2026-06-30

## 1. 背景

当前项目已经具备以下基础能力：

- 已有点击锚点（Anchors）配置与编辑能力
- 已有 OCR 识别框（Regions）配置与编辑能力
- 已有基础点击、输入、OCR 执行能力
- 已有基于 `AppProfile` 的配置保存与加载能力

用户希望在当前 WPF 桌面应用中新增一个“流程编辑”标签页，用可视化方式维护多个命名自动化流程。流程中的事件需要能复用现有锚点与 OCR 框，并支持拖拽排布、条件连线、草稿节点和文本输入节点。

## 2. 目标

本次设计的目标是提供一个集成在主窗口中的节点式流程编辑器，满足以下能力：

- 一个配置文件内可保存多个命名流程
- 在新标签页中可视化编辑流程
- 节点可自由上下左右拖放，并持久化画布坐标
- 支持点击节点、OCR 节点、输入文本节点
- 点击节点可选择已有点击位置，并支持按住修饰键后点击
- OCR 节点可选择已有 OCR 识别框
- 节点之间支持连线，只有从开始节点可达的节点会被实际执行
- 未接入主流程的节点允许作为草稿或临时调试节点存在
- 连线支持字符串包含关系与数值大小关系条件判断
- 连线视觉表现为自适应曲线

## 3. 非目标

本次不包含以下内容：

- 并行分支执行
- 子流程调用
- 多入口流程
- 复杂逻辑组合条件（AND / OR / 嵌套表达式）
- 变量系统与跨流程共享上下文
- 完整的流程运行可视动画回放
- 第三方节点编辑框架引入

## 4. 总体方案

在主窗口新增一个“流程编辑”标签页，采用三栏结构：

- 左侧：流程列表
- 中间：节点画布
- 右侧：属性面板

每个流程是一个自由摆放的有向图。运行入口固定为一个不可删除的开始节点。运行时仅执行从开始节点可达的节点。图中允许存在未连入主流程的节点，这些节点不会在正式运行时触发。

## 5. UI 设计

### 5.1 左侧流程列表

用于管理多个命名流程：

- 新增流程
- 删除流程
- 选择当前编辑流程
- 修改流程名称

每个流程创建时自动生成一个开始节点。

### 5.2 中间节点画布

画布用于展示和编辑当前流程的节点图：

- 节点支持上下左右自由拖放
- 节点位置以 `X/Y` 持久化保存
- 节点之间显示曲线连线
- 画布支持新增节点
- 画布支持选择节点与连线
- 节点允许处于未连入主流程的草稿状态

画布顶部工具栏建议提供：

- 新增点击节点
- 新增 OCR 节点
- 新增输入文本节点
- 自动整理视图

### 5.3 右侧属性面板

属性面板根据当前选中对象显示不同内容：

- 选中流程：编辑流程名称
- 选中节点：编辑节点类型对应参数
- 选中连线：编辑连线条件和优先级

## 6. 节点类型

### 6.1 开始节点

- 每个流程固定一个
- 自动创建
- 不可删除
- 用作运行入口

### 6.2 点击节点

点击节点用于触发鼠标点击操作：

- 可编辑节点名称
- 可选择已有点击锚点
- 可配置修饰键列表

第一版支持的修饰键：

- `Ctrl`
- `Shift`
- `Alt`

点击时按顺序执行：

- 按下所选修饰键
- 执行鼠标左键点击
- 释放修饰键

### 6.3 OCR 节点

OCR 节点用于对指定识别框执行 OCR：

- 可编辑节点名称
- 可选择已有 OCR 识别框

OCR 节点输出两个结果供后续条件使用：

- 字符串结果
- 尝试解析后的数值结果

如果数值解析失败，则数值条件判断视为不满足。

### 6.4 输入文本节点

输入文本节点用于把固定字符串粘贴到当前焦点输入位置：

- 可编辑节点名称
- 可编辑目标文本
- 可配置输入前是否先清空输入框

当启用“先清空”时，执行顺序为：

- `Ctrl+A`
- `Backspace`
- 粘贴文本

未启用时直接粘贴文本。

## 7. 连线模型

连线用于表示节点间的跳转关系。

每条连线至少包含：

- 起始节点
- 目标节点
- 顺序号
- 条件配置

同一个节点允许有多条出线。

### 7.1 无条件连线

无条件连线表示默认跳转路径。

### 7.2 条件连线

条件连线只有在判断结果满足时才会被采用。

第一版支持以下两类条件：

- 字符串条件
  - 包含
  - 不包含
- 数值条件
  - `>`
  - `>=`
  - `=`
  - `<=`
  - `<`

第一版条件值来源默认依赖最近一次有效 OCR 节点输出。数据模型中预留 `SourceNodeId`，便于后续扩展为显式指定条件来源节点。

## 8. 运行规则

### 8.1 可执行范围

运行从开始节点开始，仅执行从开始节点可达的节点。

以下节点不会被触发：

- 未连到开始节点路径上的节点
- 仅用于草稿的孤立节点

### 8.2 节点执行语义

- 开始节点：仅作为入口，不执行外部动作
- 点击节点：执行修饰键点击
- OCR 节点：执行 OCR，并刷新最近 OCR 结果上下文
- 输入文本节点：根据配置选择是否先清空，再粘贴文本

### 8.3 出线选择规则

每次节点执行结束后，按如下规则选择下一条出线：

1. 按顺序检查条件连线
2. 选择第一条满足条件的条件连线
3. 若无条件连线满足，则选择第一条无条件连线
4. 若无任何可走出线，则流程结束

“第一条”以用户可见的连线顺序定义。

### 8.4 条件判断规则

- 字符串条件针对最近一次 OCR 的字符串结果进行判断
- 数值条件针对最近一次 OCR 的数值结果进行判断
- 若当前不存在有效 OCR 结果，则依赖 OCR 的条件一律不满足
- 若数值解析失败，则数值比较不满足

### 8.5 循环保护

允许图中出现环，但运行时需要最大步数限制，默认建议为 `100` 步。

超过最大步数时：

- 终止执行
- 给出明确错误提示

### 8.6 非法关系限制

第一版应禁止以下情况：

- 节点连到自己
- 连线目标不存在
- 多个开始节点

## 9. 连线视觉设计

连线使用自适应贝塞尔曲线展示，而不是硬折线。

要求如下：

- 节点移动时曲线实时刷新
- 起点和终点尽量贴近节点边缘
- 多条线并存时仍具备可读性
- 选中连线时有明显高亮

第一版优先保证：

- 正确性
- 可读性
- 可编辑性

不追求复杂动画。

## 10. 数据模型设计

### 10.1 FlowDefinition

- `Connections`

### 10.2 FlowNode

- `Id`
- `Name`
- `Type`
- `X`
- `Y`
- `IsDraft`
- `Click`
- `Ocr`
- `TextInput`

### 10.3 FlowConnection

- `Id`

### 10.4 FlowCondition

- `Kind`
- `SourceNodeId`

### 10.5 ClickNodeSettings

### 10.6 OcrNodeSettings

## 11. WPF 落地方式

第一版不引入第三方流程图库，使用 WPF 原生控件实现。

推荐方式：

- 画布使用 `Canvas`
- 节点层使用 `ItemsControl`
- 节点位置通过 `Canvas.Left/Top` 绑定
- 连线层使用 `Path`
- 曲线路径由 view model 或辅助几何类计算

这样可以最大限度保持当前项目结构简单可控。

## 12. ViewModel 设计

建议新增以下视图模型：

### 12.1 FlowEditorViewModel

负责：

- 当前流程列表
- 当前选中流程
- 当前选中节点
- 当前选中连线
- 新增删除流程与节点
- 拖拽状态同步

### 12.2 FlowNodeViewModel

负责：

- 单节点显示状态
- 节点位置
- 节点标题
- 节点类型
- 节点是否选中

### 12.3 FlowConnectionViewModel

负责：

- 起终点引用
- 曲线路径
- 条件标签摘要
- 选中状态

## 13. 与现有能力的复用

### 13.1 锚点复用

点击节点的锚点选择直接使用现有 `AnchorEntries`。

### 13.2 OCR 框复用

OCR 节点的识别框选择直接使用现有 `RegionEntries`。

### 13.3 输入执行复用

输入文本节点复用当前输入自动化能力：

- `Ctrl+A`
- `Backspace`
- Unicode 文本输入

### 13.4 点击执行扩展

现有输入执行层需要从“普通点击 / Ctrl 点击”扩展为“任意修饰键组合点击”。

## 14. 保存与兼容策略

### 14.1 保存

流程与原有配置一起保存到同一个 profile JSON 中。

### 14.2 老配置兼容

若历史配置中不存在 `flows` 字段：

- 自动使用空集合
- 不强制创建默认流程

这样不会影响已有坐标、OCR 参数和输出目录等旧配置。

## 15. 校验策略

### 15.1 保存前校验

保存前采用宽松校验，允许：

- 草稿节点
- 孤立节点
- 暂未接入主流程的调试节点

仅阻止真正损坏数据的情况，例如：

- 节点 id 重复
- 连线 id 重复
- 连线目标不存在
- 开始节点缺失或重复

### 15.2 运行前校验

运行前采用严格校验，要求：

- 存在唯一开始节点
- 从开始节点至少可达一个可执行节点
- 所有会被执行到的节点配置完整
- 所有会被执行到的条件连线配置完整
- 最大步数保护已启用

## 16. 测试策略

### 16.1 Core 配置与持久化测试

- 多流程保存与加载 round-trip
- 节点位置保存与恢复
- 连线和条件保存与恢复
- 老配置缺少 `flows` 时兼容

### 16.2 Core 运行规则测试

- 仅执行从开始节点可达的节点
- 多条件同时满足时只走第一条
- 无条件连线兜底逻辑正确
- OCR 数值解析失败时数值条件不命中
- 有环时最大步数保护生效

### 16.3 App 视图模型与资源测试

- 新标签页资源存在
- 新增删除流程可更新状态
- 选中不同节点类型时属性面板字段正确
- 选中连线时条件编辑区可见

## 17. 第一版范围

第一版必须包含：

- 多命名流程
- 自由摆放节点画布
- 开始节点
- 点击节点
- OCR 节点
- 输入文本节点
- 条件连线
- 草稿节点不执行
- 曲线连线
- 配置保存与加载

第一版暂不包含：

- 并行执行
- 子流程
- 多入口
- 条件组合表达式
- 复杂变量系统
- 高级运行回放动画

## 18. 风险与取舍

### 18.1 自绘画布复杂度

自绘节点和曲线连线会引入一定 UI 交互复杂度，但可避免第三方框架接入成本和风格不统一问题。

### 18.2 条件来源语义

第一版默认使用最近一次 OCR 输出作为条件来源，能快速落地，但后续若出现多个 OCR 节点交替使用的复杂流程，建议升级为显式指定 `SourceNodeId` 的 UI。

### 18.3 执行路径确定性

多条条件线同时满足时只走第一条，虽然限制了多路并发能力，但能保持执行结果稳定可预期，适合第一版。

## 19. 实现顺序建议

建议实现顺序如下：

1. 扩展 `Core` 数据模型与 JSON 持久化
2. 增加流程校验与运行规则单元测试
3. 新增流程编辑相关 view model
4. 在主窗口添加流程编辑标签页
5. 实现节点画布与拖拽
6. 实现曲线连线与连线属性编辑
7. 扩展执行层支持修饰键点击和文本输入节点
8. 增加流程运行前校验与基础日志反馈

## 20. 验收标准

以下条件全部满足时视为本设计落地成功：

- 用户可在一个配置文件中创建、命名并保存多个流程
- 用户可在画布上自由拖动节点并保存位置
- 点击节点只能从已有锚点中选择目标
- OCR 节点只能从已有识别框中选择目标
- 输入文本节点支持“先清空再粘贴”
- 未从开始节点连通的节点不会在运行中执行
- 条件连线支持字符串包含和数值大小比较
- 连线显示为可读的自适应曲线
- 老配置加载不受影响
